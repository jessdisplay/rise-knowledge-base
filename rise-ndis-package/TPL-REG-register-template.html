[Register Title]

Document type: Register. The running log that proves a process operates over time. Worked example: REG-INC-01 Incident Register.

How to use this template. This document specifies the register; the register itself lives as a spreadsheet (or a system table) built to this specification. Auditors read registers before anything else: a current, complete register is the strongest single piece of evidence that a process is real. An empty register plus a perfect policy is a red flag, not a pass.

1. Document control

Field Entry

Maintained by (role) [Quality Manager]
Reviewed [e.g. monthly by owner; quarterly summary to Board]

3. Column specification

[One row per column: name · type · allowed values · why it exists. Keep the register lean — every column must serve retrieval, reporting or the audit trail.]

Example for REG-INC-01:

Column Type / values Why
Incident ID auto number Stable reference
Date of incident / date recorded dates Timeliness is itself audited
Participant ref ID (not full name) Privacy-minimised link to CRM
Summary short text Retrieval
Severity minor / moderate / major Trend reporting
Reportable? yes / no Splits the statutory pathway
Notified to Commission (date) date Deadline evidence, per PRO-INC-02
Corrective action ref REG-QMS-01 ID Closes the learning loop
Status open / closed Nothing left hanging
